Hash tables are one of the most important data structures in computer science, providing average-case O(1) time complexity for insertion, deletion, and lookup operations. A hash table uses a hash function to map keys to indices in an array, called buckets. The efficiency of a hash table depends critically on the quality of the hash function and the collision resolution strategy.

Common collision resolution strategies include chaining and open addressing. In chaining, each bucket contains a linked list of elements that hash to the same index. In open addressing, when a collision occurs, the algorithm probes subsequent locations in the array. Linear probing, quadratic probing, and double hashing are common open addressing techniques. The load factor, defined as the ratio of elements to buckets, affects the performance significantly.

The universal hashing technique selects hash functions randomly from a family of hash functions to minimize collisions. A good hash function distributes keys uniformly across buckets and minimizes clustering. Cryptographic hash functions like SHA-256 provide additional properties such as preimage resistance and collision resistance, but are computationally more expensive than non-cryptographic hash functions.

Bloom filters use multiple hash functions to test set membership probabilistically. A Bloom filter can have false positives but never false negatives, making it useful for cache lookups and network routing. The false positive rate depends on the number of hash functions, the size of the bit array, and the number of elements inserted. Cuckoo hashing provides worst-case O(1) lookup time by using two hash functions and relocating elements upon collision.
